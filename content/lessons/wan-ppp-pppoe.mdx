## WAN คืออะไร

**WAN (Wide Area Network)** เชื่อมเครือข่ายที่อยู่ห่างกันทางภูมิศาสตร์ เช่น สำนักงานใหญ่กับสาขา หรือบ้านกับ ISP โดยมักใช้บริการของผู้ให้บริการ

| ยุค / เทคโนโลยี | ลักษณะ |
|---|---|
| Leased line (E1/T1, SDH) + **PPP/HDLC** | ลิงก์ serial แบบ point-to-point เช่าเฉพาะ |
| Frame Relay, ATM | packet/cell switching แบบเก่า |
| **Ethernet + PPPoE** | broadband ตามบ้าน/สาขา (FTTx, DSL) |
| MPLS VPN, SD-WAN | WAN ขององค์กรในปัจจุบัน |

ชั้น data link ของ WAN ต่างจาก Ethernet: ลิงก์ point-to-point **ไม่ต้องใช้ MAC address** เพราะปลายทางมีแค่ตัวเดียว

## PPP — Point-to-Point Protocol

PPP เป็นโปรโตคอล data link สำหรับลิงก์ point-to-point (full-duplex, synchronous/asynchronous) มีความสามารถที่ HDLC ไม่มี:

- **Authentication** (PAP / CHAP)
- เจรจาพารามิเตอร์ของลิงก์ (MRU, magic number สำหรับตรวจ loop)
- แจก IP address ให้ปลายอีกฝั่งได้ (ผ่าน IPCP)
- รองรับหลาย network protocol ผ่าน NCP

### สามขั้นตอนการสร้างลิงก์

<Topology name="m13-ppp" />

```text
Dead → Establish (LCP) → Authenticate (PAP/CHAP) → Network (NCP เช่น IPCP) → Open
                ↑                       │ ล้มเหลว
                └──────── Terminate ←───┘
```

1. **LCP (Link Control Protocol)** — เจรจา MRU, วิธี authentication, magic number ถ้าทั้งสองฝั่งตอบ Configure-Ack กัน LCP จะ **Opened**
2. **Authentication** — ถ้ากำหนดไว้ (ไม่บังคับ) ผ่านแล้วจึงไปต่อ ล้มเหลว → ปิดลิงก์
3. **NCP** — เช่น **IPCP** เจรจา IP address แล้วจึงส่ง IP packet ได้

<Callout type="tip">
magic number ที่สุ่มขึ้นใช้ตรวจ **loopback**: ถ้าได้รับ Configure-Request ที่มี magic number เดียวกับของตัวเอง แปลว่าลิงก์วนกลับมาหาตัวเอง
</Callout>

### PAP vs CHAP

| | **PAP** | **CHAP** |
|---|---|---|
| การจับมือ | 2-way: ส่ง username + password | 3-way: Challenge → Response → Success/Failure |
| password บนสาย | **plaintext** | ไม่ส่ง password — ส่งค่า **MD5 hash** ของ (ID + password + challenge) |
| ผู้เริ่ม | ผู้ถูกตรวจสอบ ส่งข้อมูลเอง | ผู้ตรวจสอบ ส่ง challenge (ค่าสุ่ม) |
| ความปลอดภัย | ต่ำ | สูงกว่า กัน replay ด้วย challenge ใหม่ทุกครั้ง |

## PPPoE — PPP over Ethernet

broadband ใช้ Ethernet ซึ่งไม่มี authentication และการคิดค่าบริการรายผู้ใช้ **PPPoE** จึงห่อ PPP ไว้ใน Ethernet frame เพื่อนำความสามารถของ PPP (authentication, แจก IP, accounting) มาใช้กับผู้ใช้จำนวนมากบนเครือข่าย Ethernet

<Topology name="m13-pppoe" />

### สองขั้นตอนของ PPPoE

**1. Discovery** (EtherType 0x8863) — หา server และสร้าง session ID

| Packet | ทิศทาง | หน้าที่ |
|---|---|---|
| **PADI** (Initiation) | client → broadcast | หา PPPoE server |
| **PADO** (Offer) | server → client | ตอบว่าพร้อมให้บริการ |
| **PADR** (Request) | client → server ที่เลือก | ขอเริ่ม session |
| **PADS** (Session-confirmation) | server → client | ยืนยัน + กำหนด **Session ID** |
| PADT (Terminate) | ฝั่งใดก็ได้ | ปิด session |

**2. Session** (EtherType 0x8864) — ทำ PPP ตามปกติ: LCP → PAP/CHAP → IPCP (ได้ IP จาก server) แล้วรับส่งข้อมูล

<Callout type="exam">
MTU ของ PPPoE คือ **1492** (1500 − 6 byte PPPoE header − 2 byte PPP protocol) — packet ใหญ่เกินอาจมีปัญหา จึงมักตั้ง TCP MSS/MTU ให้ต่ำลง
</Callout>

## สรุปท้ายบท

- PPP: LCP → authentication (เลือกได้) → NCP/IPCP
- PAP ส่ง password ตรง ๆ, CHAP ใช้ challenge + hash (MD5)
- PPPoE: Discovery (PADI → PADO → PADR → PADS) แล้วจึง PPP session · MTU 1492
- AR client: `interface Dialer` + `pppoe-client dial-bundle-number` + default route ไป Dialer + Easy IP
