Static Routing

Static Routing

วัตถุประสงค์

  • อ่าน routing table ของ VRP และบอกความหมายของแต่ละคอลัมน์ได้
  • อธิบายลำดับการเลือก route: longest prefix match → preference → cost
  • ตั้งค่า static route, default route, floating static route และ summary route ได้
  • วิเคราะห์ปัญหา routing loop / black hole ที่เกิดจาก static และ default route

Route มาจากไหน

Router ส่ง packet ตาม routing table ซึ่ง route มาจาก 3 แหล่ง

แหล่งProto ใน tablePreference default
Direct (subnet ที่ต่ออยู่และ interface up)Direct0
Static (ผู้ดูแลกำหนดเอง)Static60
Dynamic routing protocolOSPF / RIP / ISIS / BGPOSPF 10, IS-IS 15, RIP 100, OSPF ASE 150, BGP 255

⚠️ กับดักที่พบบ่อย

บน Huawei preference ยิ่งน้อยยิ่งดี และใช้เปรียบเทียบ route ปลายทางเดียวกันที่มาจาก ต่างโปรโตคอล ส่วน cost (metric) ใช้เปรียบเทียบ route ภายในโปรโตคอลเดียวกัน — ค่า default ต่างจาก Cisco (static ของ Cisco คือ AD 1) อย่าจำสลับ

ลำดับการเลือก route

  1. Longest prefix match — ดู route ที่ match IP ปลายทางและมี mask ยาวที่สุด ก่อนเสมอ
  2. ถ้ามีหลาย route ที่ prefix เดียวกันจากหลายแหล่ง → เลือก preference ต่ำสุด
  3. ถ้ามาจากโปรโตคอลเดียวกัน → เลือก cost ต่ำสุด ถ้าเท่ากันจะทำ ECMP (load balancing)

ตัวอย่าง: packet ไป 10.1.1.5 ขณะที่ table มี 10.0.0.0/8 (OSPF), 10.1.0.0/16 (Static) และ 10.1.1.0/24 (RIP) → เลือก 10.1.1.0/24 ทั้งที่ RIP มี preference แย่ที่สุด เพราะ prefix ยาวที่สุดชนะก่อน

Static route

รูปแบบคำสั่ง:

ip route-static <ปลายทาง> <mask หรือ prefix> { <next-hop> | <interface> [next-hop] } [preference <ค่า>]

🎯 จุดที่มักออกสอบ

การสื่อสารสำเร็จต้องมีทั้ง ขาไปและขากลับ โจทย์ "ping ไม่ผ่าน" ที่พบบ่อยที่สุดคือ router ปลายทางไม่มี route กลับมาหา subnet ต้นทาง

ระบุ next hop หรือ outbound interface?

  • Point-to-point (เช่น serial ที่ใช้ PPP) — ระบุแค่ outbound interface ได้ เพราะปลายอีกด้านมีตัวเดียว
  • Broadcast (Ethernet) — ต้องระบุ next hop ถ้าระบุแค่ interface router จะไม่รู้ว่าจะ ARP หาใคร

Default route

0.0.0.0/0 match ทุกปลายทาง แต่เพราะ prefix สั้นที่สุดจึงถูกใช้เป็นตัวเลือกสุดท้าย — นิยมใช้ที่ router ขอบเครือข่ายชี้ออก ISP

⚠️ Routing loop จาก default route

ถ้า R1 ชี้ default ไป R2 และ R2 ชี้ default กลับมา R1 แล้วมี packet ไปยัง subnet ที่ไม่มีใครรู้จัก packet จะวิ่งไปมาจน TTL หมด วิธีแก้คือใส่ summary route ชี้ไป NULL0 บน router ที่เป็นเจ้าของ address block เพื่อทิ้ง packet ที่ไม่มีปลายทางจริง

[R2]ip route-static 172.16.0.0 16 NULL0

Floating static route

static สำรองที่ตั้ง preference สูงกว่า เส้นหลัก จึงยังไม่ถูกใช้จนกว่าเส้นหลักจะหายไปจาก table

ถ้าตั้ง preference ของสองเส้นให้ เท่ากัน จะได้ load balancing (ECMP) แทน

📝 หมายเหตุ

floating route จะทำงานเมื่อ interface ของเส้นหลัก down (route หายจาก table) แต่ถ้าปัญหาเกิดไกลออกไปขณะที่พอร์ตยัง up static route หลักจะยังค้างอยู่ — ในงานจริงจึงใช้คู่กับ BFD/NQA ตรวจปลายทาง

Route summarization

รวมหลาย route เป็นเส้นเดียวเมื่อ next hop เดียวกัน เช่น 192.168.0.0/24–192.168.3.0/24 → ip route-static 192.168.0.0 22 10.0.12.2 (วิธีหา prefix ดู M3)

คำสั่งตรวจสอบ

คำสั่งใช้ดู
display ip routing-tableทั้งตาราง
display ip routing-table 192.168.3.10route ที่ใช้จริงสำหรับปลายทางนี้ (longest match)
display ip routing-table protocol staticเฉพาะ static (แยก active/inactive)
display ip routing-table verboseรายละเอียด เช่น state, age, relay next hop
tracert 192.168.3.10ดูเส้นทางที่ packet วิ่งจริง

สรุปท้ายบท

  • Longest prefix match มาก่อน preference และ cost เสมอ
  • Huawei: Direct 0, OSPF 10, Static 60, RIP 100, OSPF ASE 150, BGP 255
  • Ethernet ต้องระบุ next hop · ต้องมี route ขากลับ
  • Floating = preference สูงกว่า, ECMP = preference/cost เท่ากัน
  • กัน loop ด้วย summary route ไป NULL0
