DHCP

DHCP

วัตถุประสงค์

  • เปรียบเทียบการกำหนด IP แบบ static กับ dynamic และบทบาทของ DHCP
  • อธิบายกระบวนการ DORA, ชนิดของ DHCP message และการต่ออายุ lease (T1/T2)
  • ตั้งค่า DHCP server แบบ global pool และ interface pool บน VRP
  • อธิบายและตั้งค่า DHCP relay เมื่อ client กับ server อยู่ต่าง subnet

ทำไมต้องใช้ DHCP

การตั้ง IP เองทีละเครื่องเสียเวลา ผิดพลาดง่าย (IP ซ้ำ, gateway ผิด) และไม่เหมาะกับอุปกรณ์ที่ย้ายที่บ่อย DHCP (Dynamic Host Configuration Protocol) แจก IP พร้อมพารามิเตอร์อื่น (mask, gateway, DNS, lease) ให้อัตโนมัติจาก address pool

  • ใช้ UDP — server port 67, client port 68
  • อุปกรณ์ที่ควรใช้ IP static: server, gateway, printer, อุปกรณ์เครือข่าย (หรือใช้ static binding ใน DHCP)

กระบวนการ DORA

Client (0.0.0.0)                                  DHCP Server
  | -- DHCP DISCOVER  (broadcast) ------------------> |   หา server
  | <------------------- DHCP OFFER  -------------- |   เสนอ IP
  | -- DHCP REQUEST   (broadcast) ------------------> |   ขอ IP ที่เลือก (แจ้ง server อื่นด้วย)
  | <------------------- DHCP ACK  ---------------- |   ยืนยัน + lease
  • REQUEST เป็น broadcast เพื่อบอก server ทุกตัวว่าเลือก offer ของใคร server ที่ไม่ถูกเลือกจะคืน IP ที่เสนอไว้
  • ก่อนใช้ IP client มักทำ gratuitous ARP ตรวจ IP ซ้ำ ถ้าซ้ำจะส่ง DECLINE
Messageใช้เมื่อ
NAKserver ปฏิเสธ REQUEST (เช่น IP ไม่ถูกต้องแล้ว) client ต้องเริ่ม DISCOVER ใหม่
DECLINEclient พบว่า IP ที่ได้ซ้ำกับเครื่องอื่น
RELEASEclient คืน IP ก่อนหมด lease
INFORMclient มี IP แล้วแต่ขอพารามิเตอร์อื่น (เช่น DNS)

Lease และการต่ออายุ

เวลาการกระทำ
T1 = 50% ของ leaseส่ง REQUEST แบบ unicast ไปยัง server เดิมเพื่อต่ออายุ (renew)
T2 = 87.5% ของ leaseถ้ายังไม่ได้ ACK ส่ง REQUEST แบบ broadcast ให้ server ใดก็ได้ (rebind)
หมด leaseหยุดใช้ IP แล้วเริ่ม DISCOVER ใหม่

lease default ของ pool บน Huawei คือ 1 วัน

ตั้งค่า DHCP server

Global address pool (ใช้กับหลาย interface/relay ได้)

Interface address pool (subnet เดียวกับ interface)

⚠️ กับดักที่พบบ่อย

ลืม dhcp enable ในระดับ system view = DHCP ไม่ทำงานแม้ตั้ง pool ครบ และถ้าใช้ global pool อย่าลืม dhcp select global บน interface ที่รับ request

DHCP relay

DISCOVER เป็น broadcast จึง ข้าม router ไม่ได้ ถ้า server อยู่ต่าง subnet ต้องให้ router (gateway ของ client) เป็น DHCP relay agent

  1. relay รับ broadcast จาก client แล้วส่งต่อแบบ unicast ไปยัง server พร้อมใส่ giaddr = IP ของ interface ที่รับ request (192.168.10.1)
  2. server ใช้ giaddr เลือก pool ที่ subnet ตรงกัน แล้วตอบกลับไปที่ relay
  3. relay ส่งคำตอบให้ client

🎯 จุดที่มักออกสอบ

  • DISCOVER/REQUEST = broadcast · T1 renew = unicast · T2 rebind = broadcast
  • UDP 67 (server) / 68 (client)
  • relay ใส่ giaddr และ server เลือก pool จาก giaddr
  • client ได้ 169.254.x.x = ติดต่อ DHCP ไม่ได้ (ดู M3)

สรุปท้ายบท

  • DORA: Discover → Offer → Request → Ack
  • lease default 1 วัน, T1 50%, T2 87.5%
  • dhcp enable + (global pool + dhcp select global) หรือ dhcp select interface
  • ต่าง subnet ใช้ dhcp select relay + dhcp relay server-ip
