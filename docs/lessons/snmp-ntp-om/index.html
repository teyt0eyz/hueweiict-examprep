SNMP, NTP และงาน O&M

วัตถุประสงค์

  • อธิบายความหมายของ network management และ O&M
  • อธิบายองค์ประกอบของ SNMP (NMS, agent, MIB, OID) และชนิดของ operation
  • เปรียบเทียบ SNMPv1/v2c/v3 และตั้งค่า SNMP บน VRP

Network management และ O&M

O&M (Operation & Maintenance) คือการดูแลให้เครือข่ายทำงานได้ต่อเนื่อง ได้แก่ เฝ้าระวังสถานะ, เก็บ log และ alarm, จัดการ configuration, วิเคราะห์ประสิทธิภาพ และแก้ปัญหา

วิธีจัดการอุปกรณ์:

วิธีลักษณะ
CLI (console / Telnet / SSH)ทีละเครื่อง ยืดหยุ่น แต่ไม่ scale (ดู M2)
Webใช้ง่าย เหมาะกับงานพื้นฐาน
SNMP + NMSจัดการและเฝ้าระวังหลายเครื่องจากศูนย์กลาง
NETCONF / API / automationยุคใหม่ ตั้งค่าแบบอัตโนมัติ (ดู M16, M17)

SNMP — Simple Network Management Protocol

องค์ประกอบ

  • NMS (Network Management Station) — ซอฟต์แวร์จัดการที่ศูนย์กลาง ส่งคำสั่งและรับ trap
  • Agent — process บนอุปกรณ์ที่ถูกจัดการ ตอบคำขอและส่ง trap
  • MIB (Management Information Base) — ฐานข้อมูลเชิงต้นไม้ของสิ่งที่จัดการได้
  • OID (Object Identifier) — ตำแหน่งของ object ใน MIB เช่น 1.3.6.1.2.1.1.5 (sysName)

Operation

Operationทิศทางหน้าที่
GetNMS → agentอ่านค่า object
GetNextNMS → agentอ่าน object ถัดไป (ใช้ไล่ทั้งตาราง / walk)
GetBulk (v2c+)NMS → agentอ่านหลาย object ในครั้งเดียว
SetNMS → agentแก้ไขค่า
Trapagent → NMSแจ้งเหตุการณ์ทันที ไม่มีการตอบรับ
Inform (v2c+)agent → NMSแจ้งเหตุการณ์ที่ NMS ต้องตอบรับ
  • ใช้ UDP: agent ฟังที่ 161 (get/set), NMS รับ trap ที่ 162

เวอร์ชัน

เวอร์ชันความปลอดภัยหมายเหตุ
SNMPv1community string (plaintext)พื้นฐาน
SNMPv2ccommunity string (plaintext)เพิ่ม GetBulk, Inform
SNMPv3USM: authentication (MD5/SHA) + encryption (DES/AES) และ VACM ควบคุมสิทธิ์แนะนำให้ใช้

⚠️ กับดักที่พบบ่อย

community string ของ v1/v2c ส่งแบบ plaintext — ใครดัก packet ได้ก็รู้ อย่าใช้ค่า default อย่าง public/private และควรจำกัด IP ของ NMS ด้วย ACL

NTP — Network Time Protocol

เวลาที่ตรงกันจำเป็นต่อการวิเคราะห์ log/alarm ข้ามอุปกรณ์, การตรวจ certificate และการคิดค่าบริการ NTP ใช้ UDP 123

Stratum

  • stratum บอกระยะห่างจากนาฬิกาอ้างอิง: นาฬิกาอ้างอิงจริง (เช่น atomic/GPS) ถือเป็นระดับ 0, server ที่ต่อโดยตรงเป็น stratum 1 แล้วเพิ่มทีละ 1 ต่อชั้น
  • ค่าที่ถูกต้องคือ 1–15; 16 = ยังไม่ sync (ใช้อ้างอิงไม่ได้)
  • ค่าน้อยกว่า = แม่นยำกว่า client มักเลือก server ที่ stratum ต่ำกว่า

หลักการคำนวณ

client ส่ง request (T1) → server รับ (T2) และตอบ (T3) → client รับ (T4)

round-trip delay = (T4 − T1) − (T3 − T2)
clock offset     = ((T2 − T1) + (T3 − T4)) / 2

โหมดการทำงาน

โหมดลักษณะ
Client/Server (unicast)client ขอเวลาจาก server ที่ระบุ — ใช้บ่อยที่สุด
Symmetric peerสอง peer sync กันได้ทั้งสองทาง
Broadcast / Multicastserver ประกาศเวลาเป็นระยะ client ฟังเอง

🎯 จุดที่มักออกสอบ

  • SNMP: agent UDP 161, trap UDP 162 · NTP: UDP 123
  • trap ไม่มีการตอบรับ, inform มีการตอบรับ
  • v3 เท่านั้นที่มี authentication + encryption จริง
  • stratum 16 = ยังไม่ sync · stratum ต่ำ = ใกล้แหล่งเวลามากกว่า

เครื่องมือ O&M อื่น ๆ

  • Syslog / info-center — ส่ง log ไปเก็บที่ server (info-center loghost <ip>)
  • LLDP — อุปกรณ์ประกาศข้อมูลตัวเองให้เพื่อนบ้าน ช่วยวาด topology (lldp enable, display lldp neighbor brief)
  • การสำรอง config — save, แล้วคัดลอก vrpcfg.zip ออกด้วย FTP/SFTP/TFTP
  • การแก้ปัญหาทีละชั้น — physical (display interface) → data link (display mac-address, display stp) → network (ping, tracert, display ip routing-table)

สรุปท้ายบท

  • SNMP = NMS + agent + MIB/OID · get/getnext/getbulk/set/trap/inform
  • v1/v2c ใช้ community (plaintext), v3 ใช้ USM (auth + privacy)
  • NTP: UDP 123, stratum 1–15 (16 = ไม่ sync), client/server เป็นโหมดหลัก
  • VRP: snmp-agent …, ntp-service unicast-server, ntp-service refclock-master
