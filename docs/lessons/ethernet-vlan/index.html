Ethernet Switching & VLAN

Ethernet Switching และ VLAN

วัตถุประสงค์

  • อธิบายโครงสร้าง Ethernet frame และชนิดของ MAC address
  • อธิบายการเรียนรู้ MAC และการตัดสินใจ flood / forward / discard ของสวิตช์
  • อธิบาย 802.1Q tag และกฎรับ-ส่ง frame ของพอร์ต access, trunk และ hybrid
  • ตั้งค่า VLAN แบบ port-based และ MAC-based บน Huawei switch
  • ทำ inter-VLAN routing ด้วย router-on-a-stick และ VLANIF ได้

Ethernet frame และ MAC address

Ethernet II frame ที่ใช้กับ IP:

Destination MACSource MACTypeDataFCS
6 byte6 byte2 byte46–1500 byte4 byte
  • frame เล็กสุด 64 byte ใหญ่สุด 1518 byte (ไม่นับ VLAN tag) — MTU ของ IP จึงเป็น 1500
  • MAC address ยาว 48 bit เขียนแบบ Huawei เป็น 5489-98aa-0001 — 24 bit แรกคือ OUI ของผู้ผลิต
  • bit ต่ำสุดของ byte แรก: 0 = unicast, 1 = multicast · FFFF-FFFF-FFFF = broadcast

สวิตช์ทำงานอย่างไร

  1. เรียนรู้ — เมื่อ frame เข้ามาที่พอร์ตใด สวิตช์บันทึก source MAC + พอร์ต + VLAN ลง MAC address table (aging time default 300 วินาที)
  2. ตัดสินใจ ตาม destination MAC
    • ไม่รู้จัก (unknown unicast), broadcast หรือ multicast → flood ออกทุกพอร์ตใน VLAN เดียวกัน ยกเว้นพอร์ตที่รับเข้ามา
    • รู้จักและอยู่พอร์ตอื่น → forward ออกพอร์ตนั้นพอร์ตเดียว
    • รู้จักแต่อยู่พอร์ตเดียวกับที่รับเข้ามา → discard

⚠️ กับดักที่พบบ่อย

สวิตช์เรียนรู้จาก source MAC เท่านั้น ไม่เคยเรียนรู้จาก destination และ broadcast frame ยังคงถูก flood แม้ MAC table จะเต็มแล้ว

VLAN และ 802.1Q

VLAN แบ่ง broadcast domain ในทางตรรกะบนสวิตช์ตัวเดียวกัน — ลด broadcast, เพิ่มความปลอดภัย, จัดกลุ่มผู้ใช้ยืดหยุ่น

802.1Q tag ยาว 4 byte แทรกระหว่าง Source MAC กับ Type:

TPIDPRICFI/DEIVID
16 bit = 0x81003 bit (802.1p ใช้ทำ QoS)1 bit12 bit

VID มี 4096 ค่า แต่ 0 และ 4095 สงวนไว้ ใช้จริงได้ 1–4094 · VLAN 1 คือ default VLAN

🎯 จุดที่มักออกสอบ

  • trunk ของ Huawei อนุญาตแค่ VLAN 1 เป็นค่า default ต้องสั่ง port trunk allow-pass vlan เพิ่มเอง
  • PVID ของ trunk สองฝั่งไม่ตรงกัน → frame ของ native VLAN ข้ามไปผิด VLAN ได้
  • โจทย์ "PC ใน VLAN เดียวกันข้ามสวิตช์คุยกันไม่ได้" มักเกิดจาก VLAN นั้นไม่ได้อยู่ใน allow-pass ของ trunk หรือไม่ได้สร้าง VLAN บนสวิตช์ตรงกลาง

ตั้งค่า port-based VLAN

⚠️ กับดักที่พบบ่อย

ก่อนเปลี่ยน link-type ของพอร์ตที่ตั้งค่าไว้แล้ว ต้องคืนค่า VLAN เดิมก่อน (เช่น undo port default vlan) มิฉะนั้น VRP จะแจ้ง error — และค่า default link-type ต่างกันไปตามรุ่น จึงควรระบุ port link-type เองทุกครั้ง

Hybrid port

VLAN แบบอื่น

  • MAC-based — จัด VLAN ตาม source MAC (ย้ายเครื่องไปพอร์ตไหนก็อยู่ VLAN เดิม) ใช้กับพอร์ต hybrid
  • IP subnet-based, protocol-based, policy-based (ผสมหลายเงื่อนไข)

Inter-VLAN routing

host ต่าง VLAN อยู่ต่าง subnet จึงต้องผ่านอุปกรณ์ layer 3 มี 3 แบบ:

  1. Router ต่อหนึ่งพอร์ตต่อหนึ่ง VLAN — ง่ายแต่เปลืองพอร์ต
  2. Router-on-a-stick — trunk เส้นเดียวไป router แล้วแบ่ง sub-interface
  3. Layer 3 switch + VLANIF — เร็วและนิยมที่สุดในแคมปัส

พอร์ตสวิตช์ที่ต่อ router ต้องเป็น trunk ที่อนุญาต VLAN 10 และ 20

📝 หมายเหตุ

VLANIF จะ up ก็ต่อเมื่อมีพอร์ตอย่างน้อยหนึ่งพอร์ตใน VLAN นั้นที่ up อยู่ ถ้าไม่มีพอร์ตใดเป็นสมาชิก VLANIF จะ down แม้ตั้ง IP แล้ว

สรุปท้ายบท

  • สวิตช์เรียนรู้ source MAC, flood unknown/broadcast, aging 300 s
  • 802.1Q tag 4 byte, TPID 0x8100, VID 12 bit (1–4094)
  • access ถอด tag · trunk ถอด tag เฉพาะ VLAN = PVID · hybrid เลือก tagged/untagged รายตัว
  • trunk Huawei allow แค่ VLAN 1 โดย default
  • router-on-a-stick ต้อง dot1q termination vid + arp broadcast enable
