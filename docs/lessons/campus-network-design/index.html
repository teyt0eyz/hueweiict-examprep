Campus Network Design

การออกแบบ Campus Network

วัตถุประสงค์

  • อธิบายองค์ประกอบและสถาปัตยกรรมแบบชั้นของ campus network
  • บอกโปรโตคอลที่ใช้ในแต่ละชั้นและเหตุผลในการเลือก
  • เข้าใจวงจรชีวิตของโครงการเครือข่าย: plan → design → deploy → O&M → optimize
  • วางแผน VLAN, IP และความทนทาน (redundancy) ของ campus ขนาดเล็กได้

Campus network คืออะไร

Campus network คือเครือข่ายภายในขององค์กรในพื้นที่จำกัด เช่น สำนักงาน โรงเรียน โรงงาน หรือโรงพยาบาล ประกอบด้วยเครือข่ายสาย, WLAN, ระบบความปลอดภัย และระบบจัดการ ขนาดมีตั้งแต่ไม่กี่สิบเครื่องจนถึงหลายหมื่นเครื่อง

ขนาดจำนวนผู้ใช้โดยประมาณโครงสร้างที่นิยม
เล็กหลักร้อย2 ชั้น (core + access)
กลางหลักพัน3 ชั้น
ใหญ่หลักหมื่นขึ้นไป3 ชั้นหรือมากกว่า แยกพื้นที่ชัดเจน

สถาปัตยกรรมแบบชั้น

ชั้นหน้าที่อุปกรณ์/เทคโนโลยีที่พบ
Accessต่อผู้ใช้/AP เข้าเครือข่าย, ควบคุมการเข้าถึงLayer 2 switch (PoE), VLAN, 802.1X/MAC auth, port security, edge port
Aggregationรวม access, เป็น gateway ของ VLAN, บังคับ policyL3 switch, VLANIF, DHCP relay, ACL, VRRP, STP root
Coreส่งข้อมูลความเร็วสูงระหว่างพื้นที่ — เรียบง่ายและเร็วL3 switch ประสิทธิภาพสูง, OSPF, Eth-Trunk, CSS/iStack
Egressออกอินเทอร์เน็ต/WANrouter/firewall, NAT, PPPoE, VPN
Data center / serverให้บริการภายในserver, storage
Network managementดูแลทั้งระบบNMS, SNMP, NTP, syslog

💡 Tip

แบ่งชั้นทำให้ขยายง่าย (เพิ่ม access ได้โดยไม่กระทบ core), จำกัดผลกระทบของปัญหา และแก้ปัญหาง่ายเพราะแต่ละชั้นมีหน้าที่ชัดเจน

การออกแบบให้ทนทาน

  • Dual-homing — access ต่อขึ้น aggregation 2 ตัว (ใช้ STP/MSTP หรือ Smart Link ตัด loop, ดู M7)
  • Eth-Trunk ระหว่าง core/aggregation เพื่อเพิ่ม bandwidth และ redundancy
  • Stacking (iStack/CSS) รวมสวิตช์หลายตัวเป็นตัวเดียวทางตรรกะ → ไม่ต้องพึ่ง STP
  • VRRP ให้ gateway สำรองกันระหว่าง aggregation สองตัว
  • ทางออกอินเทอร์เน็ตหลายเส้น + floating static route (ดู M4)

วงจรชีวิตของโครงการเครือข่าย

Planning → Design → Deployment → Operation & Maintenance → Optimization
   ↑                                                              │
   └──────────────────────────────────────────────────────────────┘
  1. Planning — สำรวจความต้องการ: จำนวนผู้ใช้, ประเภทบริการ, bandwidth, งบประมาณ, การเติบโตในอนาคต
  2. Design — ออกแบบ topology, VLAN/IP, routing, ความปลอดภัย, redundancy และเลือกอุปกรณ์
  3. Deployment — ติดตั้ง ตั้งค่า และทดสอบ (เช่น ทดสอบ failover)
  4. O&M — เฝ้าระวัง สำรอง config อัปเกรด แก้ไขปัญหา
  5. Optimization — ปรับปรุงเมื่อความต้องการเปลี่ยนหรือพบคอขวด

🎯 จุดที่มักออกสอบ

  • core: เร็วและเรียบง่าย ไม่ใส่ policy หนัก ๆ · aggregation: gateway + policy · access: ต่อผู้ใช้ + ความปลอดภัยที่พอร์ต
  • ลืม route กลับ บน egress router คือปัญหาที่พบบ่อยที่สุดเมื่อมีหลาย subnet
  • วงจรชีวิต: plan → design → deploy → O&M → optimize

O&M และการปรับปรุง

  • สำรอง config เป็นระยะ (save + ส่งออกไปเก็บนอกอุปกรณ์), ตั้ง NTP ให้ log มีเวลาที่ถูกต้อง (M15)
  • เฝ้าดู CPU, memory, interface error, การใช้ bandwidth ผ่าน SNMP/NMS
  • ปัญหาที่พบบ่อยและคำสั่งตรวจ: display interface brief, display vlan, display stp brief, display ip routing-table, display ip pool, display nat session all

สรุปท้ายบท

  • campus แบ่งเป็น access / aggregation / core / egress (+ DC, management)
  • ทนทานด้วย dual-homing, Eth-Trunk, stacking, VRRP, เส้นทางสำรอง
  • วางแผน VLAN/IP ให้เป็นระบบและสรุปเส้นทางได้
  • วงจรชีวิต: plan → design → deploy → O&M → optimize
