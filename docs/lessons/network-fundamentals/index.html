Network Fundamentals & TCP/IP

พื้นฐานเครือข่ายและ TCP/IP

วัตถุประสงค์

  • อธิบายองค์ประกอบของเครือข่าย ประเภทเครือข่าย (LAN/MAN/WAN) และ topology แบบต่าง ๆ ได้
  • เปรียบเทียบ OSI 7 layer กับ TCP/IP model และบอกชื่อ PDU ของแต่ละชั้นได้
  • อธิบายกระบวนการ encapsulation / decapsulation ตั้งแต่ application จนถึงสายสัญญาณ
  • เข้าใจหลักการของ TCP (3-way handshake, 4-way close, sequence/ack, window) เทียบกับ UDP
  • อธิบายโครงสร้าง IPv4 header, ICMP และการทำงานของ ARP ได้

เครือข่ายคืออะไร

เครือข่าย (network) คือกลุ่มอุปกรณ์ที่เชื่อมต่อกันเพื่อ แลกเปลี่ยนข้อมูลและแบ่งปันทรัพยากร อินเทอร์เน็ตคือ "เครือข่ายของเครือข่าย" ที่ร้อยเครือข่ายนับล้านเข้าด้วยกันผ่าน router

อุปกรณ์หลักที่ต้องรู้จักในระดับ HCIA:

อุปกรณ์ทำงานที่ layerหน้าที่หลัก
Hub / Repeater1 (Physical)ขยายสัญญาณ ส่งทุกพอร์ต อยู่ใน collision domain เดียวกัน
Switch2 (Data link)ส่งต่อ frame ตาม MAC address table แยก collision domain ต่อพอร์ต
Router3 (Network)ส่งต่อ packet ตาม routing table แยก broadcast domain
Firewall3–7ควบคุมการผ่านของ traffic ตาม security policy แบ่ง security zone
AP / AC2ให้บริการ WLAN (ดู M11)

ประเภทเครือข่ายตามขนาด

  • LAN (Local Area Network) — ครอบคลุมพื้นที่เล็ก เช่น อาคารหรือแคมปัส ความเร็วสูง ความหน่วงต่ำ องค์กรเป็นเจ้าของเอง
  • MAN (Metropolitan) — ระดับเมือง
  • WAN (Wide Area Network) — ข้ามเมือง/ประเทศ มักเช่าวงจรจากผู้ให้บริการ (ดู M13 เรื่อง PPP/PPPoE)

OSI 7 layer กับ TCP/IP

แบบจำลองแบ่งชั้น (layered model) ช่วยให้แต่ละชั้นทำหน้าที่ของตัวเองและคุยกับชั้นเดียวกันของอีกฝั่ง (peer-to-peer) โดยอาศัยบริการของชั้นที่อยู่ข้างล่าง

* ARP มักถูกจัดไว้ระหว่าง layer 2 และ 3 เพราะใช้ IP address แต่ถูกส่งใน Ethernet frame โดยตรง (EtherType 0x0806)

⚠️ กับดักที่พบบ่อย

ระวังสับสน ARP กับ RARP และอย่าลืมว่า OSPF ทำงานบน IP โดยตรง (protocol number 89) ไม่ได้ใช้ TCP หรือ UDP

Encapsulation

เมื่อส่งข้อมูล แต่ละชั้นจะ เติม header ของตัวเองครอบข้อมูลจากชั้นบน:

Data
[TCP header | Data]                               ← Segment
[IP header | TCP header | Data]                   ← Packet
[Eth header | IP | TCP | Data | FCS]              ← Frame
0101010101...                                     ← Bits

ฝั่งรับทำกลับกัน (decapsulation) โดยอ่านฟิลด์ที่บอกว่าชั้นบนเป็นอะไร:

  • Ethernet ดู Type: 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6, 0x8100 = VLAN tag
  • IP ดู Protocol: 1 = ICMP, 6 = TCP, 17 = UDP, 89 = OSPF
  • TCP/UDP ดู Port ปลายทาง เพื่อส่งให้แอปพลิเคชันที่ถูกต้อง

TCP 3-way handshake และ 4-way close

Client                          Server
  | --- SYN (seq=x) ------------> |
  | <-- SYN+ACK (seq=y, ack=x+1)  |
  | --- ACK (ack=y+1) ----------> |     → ESTABLISHED

  | --- FIN ---------------------> |
  | <-- ACK ---------------------- |
  | <-- FIN ---------------------- |
  | --- ACK ---------------------> |     → client เข้า TIME_WAIT
  • Sequence number นับเป็นจำนวน byte; ACK number = byte ถัดไปที่คาดว่าจะได้รับ
  • Window คือปริมาณข้อมูลที่ฝั่งรับยังรับได้ — ใช้ทำ flow control (sliding window)
  • การปิดใช้ 4 ขั้นเพราะ TCP เป็น full-duplex แต่ละทิศต้องปิดแยกกัน

🎯 จุดที่มักออกสอบ

  • ACK number = sequence ที่ได้รับ + จำนวน byte ของข้อมูล (หรือ +1 สำหรับ SYN/FIN)
  • เลือก UDP เมื่อ "ต้องการความเร็ว/real-time ยอมเสีย packet บ้าง" — VoIP และวิดีโอสดคือคำตอบคลาสสิก

Network layer: IPv4, ICMP, ARP

ฟิลด์สำคัญใน IPv4 header (20 byte ขั้นต่ำ)

  • Version (4), IHL, ToS/DSCP สำหรับ QoS
  • Total Length, Identification / Flags / Fragment Offset ใช้ทำ fragmentation
  • TTL — ลดลง 1 ทุกครั้งที่ผ่าน router ถ้าเหลือ 0 จะถูกทิ้งและส่ง ICMP Time Exceeded กลับ (กันวนลูปไม่รู้จบ)
  • Protocol — บอกชั้นบน
  • Header checksum, Source / Destination IP

ICMP

ARP — จาก IP หา MAC

ก่อนส่ง frame ใน LAN ต้องรู้ MAC ปลายทาง:

  1. ดู ARP cache ก่อน ถ้าไม่มีจึงส่ง ARP Request แบบ broadcast (FFFF-FFFF-FFFF) ถามว่า "ใครมี IP นี้"
  2. เจ้าของ IP ตอบ ARP Reply แบบ unicast กลับมา และทั้งสองฝั่งบันทึกลง cache
  3. ถ้าปลายทางอยู่ต่าง subnet host จะ ARP หา MAC ของ default gateway แทน — IP ปลายทางใน packet ไม่เปลี่ยน แต่ MAC ปลายทางใน frame เป็นของ gateway
  • Gratuitous ARP — ประกาศ IP ของตัวเอง ใช้ตรวจ IP ซ้ำและอัปเดต cache ของเครื่องอื่น
  • Proxy ARP — router ตอบ ARP แทนเครื่องที่อยู่อีก subnet

⚠️ กับดักที่พบบ่อย

เมื่อ packet วิ่งผ่าน router หลาย hop: IP ต้นทาง/ปลายทางคงเดิม (ถ้าไม่มี NAT) แต่ MAC ต้นทาง/ปลายทางเปลี่ยนทุก hop — โจทย์ถามบ่อยมาก

สรุปท้ายบท

  • Switch แยก collision domain; router แยก broadcast domain
  • จำ PDU: Data → Segment → Packet → Frame → Bit
  • TCP เชื่อถือได้ (handshake, ack, window) ส่วน UDP เบาและเร็ว (header 8 byte)
  • TTL กันลูป, ICMP type 8/0 คือ ping, type 11 คือ tracert
  • ARP request = broadcast, reply = unicast และ MAC เปลี่ยนทุก hop
